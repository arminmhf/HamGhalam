# هم‌قلم برای Claude Code (نسخهٔ ۴٫۰)

پلاگینی برای Claude Code که فارسیِ تولیدشده در پروژه‌ها را به فارسیِ یک کپی‌رایتر فارسی‌زبان نزدیک می‌کند: متن سایت، توضیح محصول، صفحهٔ «دربارهٔ ما»، پیام‌های رابط کاربری، ایمیل و کپشن. این کار با سه ابزار انجام می‌شود:

- **اسکیل:** فرایند نوشتن و ویرایش را تعیین می‌کند.
- **ویراستار مستقل:** متن فارسی را بدون دیدن بریف انگلیسی می‌خواند.
- **hook:** هر رشتهٔ فارسی‌ای را که وسط یک تسک کدنویسی نوشته می‌شود، بلافاصله بررسی می‌کند.

همهٔ قاعده‌ها و مثال‌های این نسخه را یک کپی‌رایتر فارسی‌زبان بازبینی کرده است (✍️ در فایل‌ها).

## چه چیزی نسبت به نسخهٔ ۳ عوض شد

| نسخهٔ ۳ | نسخهٔ ۴ | چرا |
|---|---|---|
| `skills` در `plugin.json` به یک فایل اشاره می‌کرد و `claude plugin validate` رد می‌شد | ساختار استاندارد `skills/hamghalam/SKILL.md` | در نصب پلاگینی، اسکیل اصلاً بارگذاری نمی‌شد |
| ۲۳ الگو که بیشترشان را مدل نوشته بود، با مثال‌های ✅ مدل‌ساز | هر الگو با حکم کپی‌رایتر. بخش تازهٔ D فهرست چیزهایی است که نباید «اصلاح» شوند | حدود نیمی از الگوهای قبلی فارسیِ معمولی را خطا می‌گرفتند (توسط، نه تنها … بلکه، سؤال بلاغی، دونقطه و فهرست، …). اصلاح آن‌ها متن را عجیب‌تر می‌کرد |
| قاعده‌هایی که مدل را به جمله‌های کوتاه و بریده هل می‌داد (ممنوعیت ویرگول بین دو جمله، «؛» فقط در رسمی، «جملهٔ کوتاه‌تر» در لحن دوستانه) | حذف شد. نشانه‌های تازه: زبان گفتاری در متن نیمه‌رسمی، اسمی که ناگفته می‌ماند، فعل مبهم | اینها همان چیزهایی است که کپی‌رایتر در خروجی واقعی دید |
| فقط فهرست «این را ننویس» | `frames.md` (تیتر بخش‌ها، دکمه‌ها، پیام‌های رابط کاربری) و `genres/` با بازنویسی‌های کپی‌رایتر به‌عنوان نمونهٔ مرجع | مدل از مثال بیشتر از قاعده یاد می‌گیرد |
| — | ویراستار مستقل `agents/persian-editor.md` که فقط متن فارسی را می‌بیند | نویسنده‌ای که بریف انگلیسی را دیده، قاب انگلیسی را نمی‌بیند |
| hook کل فایل را لینت می‌کرد و فقط خطاهای E را برمی‌گرداند | فقط متن همان Write/Edit را لینت می‌کند و اگر اسکیل در جلسه بارگذاری نشده باشد یک بار یادآوری می‌کند | خطوط قدیمی فایل به اسم «تو نوشتی» گزارش می‌شدند و مهم‌ترین نشانه‌ها به مدل نمی‌رسید |
| `evals/tasks.md` بدون هیچ نتیجهٔ ثبت‌شده | ۱۰ تسک در قالب `claude plugin eval` با arm بدون پلاگین، به‌علاوهٔ روبریک انسانی | بدون سنجش، هر تغییر حدس است |
| قاعدهٔ «هیچ‌وقت چیزی نساز» نبود | قدم ۰: واقعیت‌ها فقط از بریف، وگرنه جای خالی | مدل شهر و تاریخ و جزئیات فرایند از خودش می‌ساخت |

## نمونه

پوشهٔ `examples/landing-hesabyar/` یک صفحهٔ اول کامل را در سه حالت نشان می‌دهد: نوشته‌شده بدون هم‌قلم، ویرایش‌شده با هم‌قلم (همراه با گزارش سه‌سطحی) و همان ویرایش پس از تأیید پیشنهادها. همه خروجی واقعی Claude Code‌اند و دستی ویرایش نشده‌اند.

## ساختار

```
hamghalam/
├── .claude-plugin/plugin.json
├── skills/hamghalam/
│   ├── SKILL.md                  فرایند نوشتن و ویرایش (دستورها انگلیسی، مثال‌ها فارسی)
│   ├── references/
│   │   ├── patterns.md           نشانه‌های ترجمه‌زدگی + بخش D: به این‌ها دست نزن
│   │   ├── frames.md             تیتر بخش‌ها، دکمه‌ها و پیام‌های ثابت
│   │   ├── genres/               landing، product، about، ui، email، social، article
│   │   ├── tones.md              چهار لحن
│   │   ├── terms.md              قاعدهٔ وام‌واژه؛ همیشه خوانده می‌شود
│   │   └── terms/                واژه‌نامهٔ حوزه‌ای (tech، finance، retail)
│   └── scripts/lint.py           لینتر
├── agents/persian-editor.md      ویراستار مستقل
├── hooks/
│   ├── hooks.json
│   └── post_write_lint.py        بعد از هر Write/Edit فقط متن تازه را لینت می‌کند
├── evals/                        c01…c15 برای claude plugin eval + tasks.md (روبریک انسانی)
└── examples/                     نمونهٔ کامل قبل و بعد
```

## نصب

- **به‌عنوان پلاگین (پیشنهادی):** این مخزن را به Claude Code معرفی کنید (مثلاً `claude --plugin-dir path/to/HamGhalam`، یا از یک marketplace). اسکیل، ویراستار مستقل و hook همه فعال می‌شوند.
- **فقط اسکیل:** پوشهٔ `skills/hamghalam` را در `~/.claude/skills/` یا `.claude/skills/` پروژه بگذارید. در این حالت ویراستار مستقل و hook در دسترس نیستند.

جلسهٔ تازه باز کنید تا پلاگین دیده شود. درستی ساختار را با `claude plugin validate .` بسنجید.

## استفاده

> متن صفحهٔ اول را بنویس. لحن نیمه‌رسمی.

> متن‌های `src/pages/checkout` را ویرایش کن.

اسکیل با توضیحش خودکار فعال می‌شود. برای فراخوانی دستی `/hamghalam:hamghalam` را بزنید.

لینتر جدا هم اجرا می‌شود:

```
python3 skills/hamghalam/scripts/lint.py --tone semi_formal src/pages/
python3 skills/hamghalam/scripts/lint.py --json file.tsx
echo "متن" | python3 skills/hamghalam/scripts/lint.py --tone friendly -
```

## نگهداری

1. **پیش از هر تغییر،** ارزیابی را با نسخهٔ قبل و بعد اجرا کنید و نتیجه را در جدول `evals/tasks.md` ثبت کنید:
   ```
   claude plugin eval . --runs 1 -j 4 --allow-tools Bash Write Edit --judge-model sonnet --keep-temp
   ```
   داور LLM («native») همان نقطهٔ کور مدل نویسنده را دارد و فقط شاخص است. حکم نهایی با مقایسهٔ کور انسانی است.
2. **الگوی تازه** فقط با حکم یک کپی‌رایتر فارسی‌زبان وارد `patterns.md` می‌شود، با مثالی که خود او نوشته است. الگویی که کپی‌رایتر رد کند به بخش D می‌رود، نه سطل زباله، تا مدل دوباره آن را «اصلاح» نکند.
3. **قاعدهٔ لینتر** باید هم روی نمونه‌های ✍️ در `genres/` و هم روی جمله‌های بخش D ساکت بماند.
4. **اصطلاح تازه** به `terms.md` (اگر عمومی است) یا فایل حوزه در `terms/` می‌رود.
5. **هر تغییر نسخه** هم‌زمان در `CHANGELOG.md`، عنوان همین فایل و `version` در `.claude-plugin/plugin.json` اعمال شود. قدم ۰ حالت ویرایش از `plugin.json` می‌خواند.

## گام بعدی: جمع‌آوری داده

این نسخه بر داوری یک کپی‌رایتر بنا شده است. برای نسخه‌های بعد، جمع‌آوری این داده‌ها برنامه‌ریزی شده است:

- **نمونه‌های انسانی:** متن‌هایی که از اول به فارسی نوشته شده‌اند، برای هر ژانر.
- **جفت‌های قبل و بعد ویراستار:** هر کدام همراه با دلیل تغییر.
- **قاب‌های واقعی:** تیترها و دکمه‌های سایت‌های فارسی.
- **پنل خوانندهٔ عادی:** برای آزمون کور «انسان یا ماشین؟».
